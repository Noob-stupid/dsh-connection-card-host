## 0. 一句话概括

在**两个 DSH 会话之间建立有状态连接**，让它们能**互相看见对方在做什么**（拉取式，零上下文消耗）、
**共享一份说好的前提**（公约盒），并在需要时**互相传话**；连接上还能**挂载卡片插件**。

## 2. 消息转发（三档权限，逐档实测）

### 三档的语义

| 档位 | 颜色 | 能发什么 | 实测结果 |
|:---|:---|:---|:---|
| **只读** `read` | ⚪ 灰 | **什么都不转发** | `say` ❌ / `ask` ❌ / `reply` ❌ — 全部拒绝 |
| **可建议** `suggest` | 🔵 蓝 | 只允许 `say`（发言） | `say` ✅ / `ask` ❌ / `reply` ❌ |
| **可写入** `write` | 🟠 橙 | 允许 `ask`/`reply`（请求对方执行） | `say` ✅ / `ask` ✅ / `reply` ✅ |

**两个方向独立设置** → 可做成不对称（如 A→B 可写入、B→A 只读）。
线上两个圆点各显示一端颜色，所以**一根线可以一端橙一端灰**。

### ⚠️ 关键澄清：权限管的是"要不要转发消息"，**不是"对方能不能干活"**

对方的干活能力与权限**完全无关** —— 它是完整会话，本来就有工具。
权限只决定**中继要不要把消息镜像过去**。

实测依据：派给对端会话的任务走 `debug/deliver` 直投通道，**根本不检查权限**，
在 `read` 档下它照样完成并交付了修复。

### 转发的真实代价（必须知道）

**投递一条消息 = 迫使对方跑一轮。** 因为：

```
followup → 进收件箱 → agent loop 必然启动新一轮
steer    → 插进正在跑的那一轮 → 当场读到并处理
inject   → 只进上下文不唤醒 → 它下次跑才看到（不逼它动）
```

前两种都会让对方**做点什么**（agent loop 没有"看到了但不理"这个状态）。

**所以「A 说话 B 感知」若靠转发实现，实际语义是「A 说话 B 必须回应」，二者分不开。**

**面板上有常驻警告条**：任一方向权限高于只读时，连接列表上方显示橙色警告。

### 默认建议

```
平时保持「只读」 → 两个会话零打扰、零消耗地互相可见（感知不受影响）
需要真的对话时才抬权限，并知道"这会让对方被唤醒并回应"
```

## 3. 协作感知 A 层：工作状态（拉取式，0 上下文成本）

### 采集什么

从 `session/event` 自动提取，**不要求模型额外产出任何东西**：

| 事件 | 提取出 |
|:---|:---|
| `tool/call` name=`todo_write` | **计划与进度**（最佳来源，模型自己写的） |
| `tool/call` name=`edit`/`write`/`read` | **在动哪些文件**（`arguments.file_path`） |
| 工具名序列 | 在做哪类活 |
| `turn/start` / `step/start` | 推进到第几轮第几步 |

### 怎么看到

| 通道 | 谁用 |
|:---|:---|
| 工具 `connection_peer_work` | 会话自己查（**对端视角**，自动解析"我是谁"） |
| 面板「对方在做什么」 | 你看（可折叠，收起时显示一行摘要 + 活动绿点） |

### 实测

对端会话调用 `connection_peer_work` 返回：

```
【session-a4a3d1a8…】
状态：正在执行命令（2 秒前）
最近动过的文件：dsh-connection-card-host/MSGE.txt
进度：第 69 轮 / 第 39 步
```

**它不需要我告诉它，就知道我在干什么。**

### 上下文成本：**0**

采集在宿主侧做，存在内存里，**从不推进任何会话的上下文**。
只有对端**主动查询**时才产生一次工具调用的往返。

## 4. 协作感知 B 层：公约盒（拉取式，0 上下文成本）

### 是什么

连接级的**共享约定**存储 —— 双方必须遵守的前提（接口、字段名、坐标方向、单位、
命名规范、文件分工边界）。

**判断标准**：对方不知道就会做错的东西。

### 怎么用

| 工具 | 作用 |
|:---|:---|
| `connection_conventions` | 查（可按关键词） |
| `connection_declare` | 声明一条（可指定取代旧约定） |

面板上也能直接增删，归属显示为「你」（人是第三方，不是 A 也不是 B）。

### 为什么是"拉"不是"推"

推送会把对方上下文慢慢填满，而且**大部分时候它根本用不上**。
做成"存在盒子里、需要时自己查"则**上下文消耗为 0**。

至于"想不起来查" —— **工具 schema 常驻上下文本身就是零成本的提醒**。

### 实测

对端会话查询返回两条约定，**归属判定正确**（能区分"我声明的"和"对方声明的"）。

## 6. 面板内安装（装到我们自己的目录）

| 来源 | 例子 |
|:---|:---|
| 本地目录 | `D:\my-cards\monitor-card` |
| 本地 tgz | `D:\downloads\card.tgz` |
| npm 包名 | `monitor-card` / `@scope/monitor-card` |
| HTTP tgz | `https://example.com/card.tgz` |

**装到 `$DSH_HOME/connection-cards/cards/<id>/`，完全不碰 profile** ——
不跑 pnpm、不改 `dsh.profile.bundles`。

**理由**：不会被 DSH 的更新破坏，也不会破坏 DSH。

### 安装校验（先校验来源，再动目标目录）

拒绝：无 `package.json` / 非法 JSON / **无 `dshCard` 字段** / **入口文件不存在**。
**校验失败绝不删旧目录**（覆盖安装要先删旧的，所以这个次序是关键）。

**实测**：坏包被拒 ✅、入口缺失被拒 ✅、合法包装上并成功渲染 ✅、卸载后模板同步消失 ✅。

## 7. 诊断（可查询，不靠翻日志）

| 能力 | 说明 |
|:---|:---|
| `awareness/diagnostics` | 被挡下的非真人来源计数（按会话、按 kind），带 `lastSeenAt` / `lastDropped` / `total` |
| 面板显示 | 「对方在做什么」展开区，**只在有东西被挡时才出现** |
| 审计日志 | `$DSH_HOME/connection-cards/audit.log`（首次留痕） |

### 为什么放进可查询的端点

**日志会被清空、会滚动** —— 只写一次的信号一旦滚掉就永久消失。
可查询的东西不怕滚动。**实测：删掉整个审计日志后，计数仍在。**

### `lastDropped` 为什么重要

计数只说"挡了多少"，说不出"**挡的是什么**"。万一框架给真人消息换了个 kind，
光看正常计数发现不了误筛 —— 有预览，误筛会当场现形。

## 8. 安全与边界

| 边界 | 状态 |
|:---|:---|
| 跨会话通道**只放行真人发言** | ✅ 宿主通知（任务完成、模型切换等）一律挡下 |
| **防回环** | ✅ 投递痕迹识别 + 跳数上限（2 跳）+ 频控 |
| 跳数上限 | ✅ 实测 `hop=1 → hop=2 → 中继停止` |
| 频控 | ✅ 分来源分桶（手动 / 中继自动互不干扰） |
| 安装隔离 | ✅ 不碰 profile |
| 卡片沙箱 | ✅ import/apply 崩溃隔离 |

### 为什么"只放行真人发言"

宿主通知**常带面向特定属主的祈使句**。实例：后台任务完成通知里有
`Read its output with job_output` —— 那是喊给**任务属主**的，
转发出去等于让对端执行一条**没发给它的指令**。

实测挡下比例：某会话 `user/message` 里 **近三分之一**是宿主生产方
（user 85 / model-selection 23 / tool-jobs 5 / goal 4 / …）。

## 11. 两个真实协作实验的结果

### 实验一：交付一张卡片包
我派任务 → 对端照协议文档产出卡片 → 我安装验收 → 渲染成功。
**结果：跑通。并炸出两个真 bug**（回环、宿主通知被转发）。

### 实验二：修复连线越界
我派任务 → **对端交回的方案比我的原版强**，找到我三个没想到的点：
- 我的 `null` 分支**正好把 bug 放回来**
- **圆点不能被收窄**（会被钉在边界上，看起来像"线的端点"而不是"行的标记"）
- 裁剪该由**画布统一做**（以后新加的形状自动被裁）

**结果：它的方案已合并。**
